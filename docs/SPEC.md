## 1. 概要

スマホゲーム「#コンパス」の **HS合わせ** を、すぐに確認できる Web アプリ。

- **HS合わせ**：相手のヒーロースキル（HS）中は無敵になる。その無敵が切れる瞬間に、自分の攻撃やHSを合わせて倒す技術。
- 利用者は「① 攻撃する側（自分）のキャラ」→「② HSを使う相手のキャラ」の順に選び、相手のHS明けに攻撃を合わせるタイミングを **文字と動画** で確認する。
- **攻撃する側**：攻撃方法はHSに限らない（ヒーロースキル・通常攻撃・スキルカードなど何でもよい）。
- **HSを使う相手**：HSを使い、そのHSが明けた瞬間（無敵が切れた瞬間）を狙われる側。
- 画面上では「合わせる側／倒す相手」ではなく、**「攻撃する側（自分）」「HSを使う相手」** と表記して、どちらがHSを使う側かを明確にする。
- データは利用者から投稿してもらう。**ログインは不要** で、誰でもすぐ投稿できる。
- 投稿は **管理者が承認したものだけ** を公開する。

### 利用者の種類
| 種類 | できること | ログイン |
|---|---|---|
| 閲覧者 | 承認済みのタイミングを見る | 不要 |
| 投稿者 | タイミング（文字・動画）を投稿する。受付番号で審査状況を確認する | 不要 |
| 管理者 | 投稿の承認・却下、キャラ管理 | Cloudflare Access（コード不要の認証） |

### 利用環境
- スマホのブラウザが中心（モバイルファースト）。PC でも崩れないこと。

## 2. 基本方針

1. **完全無料で運用する**（独自ドメイン代を除く）。すべて Cloudflare の無料枠で構成する。
2. **自動停止しない**。アクセスが少ない期間があっても止まらない構成にする。
3. **動画はアプリに直接アップロード** する（YouTube や X のリンクではない）。
4. **未承認のデータと動画は、一般の利用者からは一切見えない**。
5. **無料枠を超えて課金が発生しないよう、アプリ側で安全装置を持つ**（8 章）。

## 3. 技術スタック

| 役割 | サービス | 無料枠の目安 |
|---|---|---|
| ホスティング・API | Cloudflare Workers（静的アセット配信込み） | 1 日 10 万リクエスト |
| データベース | Cloudflare D1（SQLite） | 5GB |
| 動画・画像の保存 | Cloudflare R2 | 10GB、転送量は無料 |
| ボット対策 | Cloudflare Turnstile | 無料 |
| 管理画面の認証 | Cloudflare Access（Zero Trust 無料プラン） | 50 ユーザーまで無料 |
| 定期処理 | Workers Cron Triggers | 無料 |

### 実装技術
- フロント：React ＋ Vite ＋ TypeScript ＋ Tailwind CSS
- API：Hono（Workers 上で動かす）
- フロントと API は **1 つの Workers プロジェクト** にまとめる（Workers の静的アセット機能を使う）。
- DB のマイグレーションは `wrangler d1 migrations` で管理する。
- ローカル開発は `wrangler dev` で、D1・R2 ともにローカルで動く状態にする。

### R2 を有効化するときの注意（README に記載すること）
- R2 の有効化には支払い方法の登録が必要。無料枠内であれば請求は発生しない。
- R2 の `r2.dev` の公開 URL はテスト用で、レート制限がかかる。本番では **独自ドメインを R2 バケットに接続する** か、**Worker 経由で配信する**。
- 本アプリでは、まず **Worker 経由で配信** し、独自ドメインを取得したら公開用バケットに接続できる構造にする（未決事項 2）。

  - 文面はオーナーが最終確認する（未決事項 5）。
- 管理画面へのリンクは、一般向けの画面には **置かない**（7 章：管理者は `/admin` を直接開く）。

### 4-0-2. このアプリについて（`/about`）
- アプリの概要、「HS明け」の説明、使い方（① 攻撃する側 → ② HSを使う相手 → 攻撃方法タブ）、画面の見方（攻撃方法・合わせる目印・動画）、投稿について、修正提案について を掲載する。
- 文面は試作版を初期値とし、管理画面の「設定」で編集できる。

### 4-1. トップ（攻撃する側のキャラ選択）
- 見出しの補足は「① 攻撃する側（自分）のキャラを選択」とする。
- 説明文は置かない（説明は「このアプリについて」にまとめる）。
- **全キャラ** を **画像付きカードのグリッド** で表示する（「合わせ可能」などのタブ分けはしない）（スマホで 5 列、PC で 6 列）。名前は2行まで表示し、それを超える分は省略する。件数の数字は表示しない。
- 各カードには、キャラ画像・キャラ名・承認済みの対戦相手数を表示する。
- 上部に検索ボックスを置く。
  - ひらがなとカタカナを区別せずに部分一致で探す。
  - 「・」「=」「'」などの記号は無視する。
- 画面下部に「投稿する」ボタンを置く（「審査状況を確認」のボタンはトップには置かない。審査状況の確認は投稿完了画面からのみ案内する）。

### 4-2. HSを使う相手の選択
- 見出しは「（攻撃する側のキャラ名）で攻撃」、補足は「② HSを使う相手（HS明けを狙う）を選択」とする。
- 全キャラを、トップと同じ **画像付きカードのグリッド（スマホ 5 列、PC 6 列）** で表示する。
  - 承認済みデータがある「登録済み」を上に、「未登録」を下にまとめる。未登録のカードも登録済みと同じ明るさで表示する（暗くしない）。
- 検索ボックスを置く（仕様は 4-1 と同じ）。

### 4-3. タイミング詳細
- 上部に VS 表示を置く。左に「攻撃する側」、右に「HSを使う相手」とラベルを付け、中央に「HS明けに合わせる ▶」と表示する。
- VS 表示の下に **攻撃方法のタブ**（ヒーロースキル／通常攻撃／ヒーローアクション／スキルカード／その他）を置く。各タブに件数を表示し、0 件のタブは薄く表示する（押すことはできる）。
  - 初期表示は、件数が 1 件以上ある最初のタブ。
- 選んだタブの攻撃方法の **タイミングだけ** を、承認済みの全エントリから集めて、上から 1, 2, 3… と番号付きのカードで表示する（承認日の古い順）。
- 各カード（1 タイミング = 1 カード）の内容：
  - 番号、目印チップ（ボイス／動き／時間／その他）
  - 合わせるタイミング（入力されたとおりに、いちばん目立つように表示する）
  - 備考（あれば）
  - 動画
  - カード下部は 2 行に分ける：
    - 1 行目：「投稿者：（ニックネーム）」（名前部分は太字）、応援コード（「応援コード XXXX」のボタン。タップでコピー）。どちらも未入力なら、この行ごと表示しない
    - 2 行目：承認日（左）、「修正を提案」ボタン（右寄せ）
- **カードはコンパクトにする**：余白と文字サイズを抑え、1 画面に多くのタイミングが収まるようにする。
- 動画はページ内で再生する（`<video controls playsinline>`）。YouTube や X など外部のアプリ・サイトは開かない。
- スマホゲームの画面録画を想定し、動画は **縦型（9:16）** で表示する。高さは画面の約 6 割（最大 440px）、幅は自動で中央寄せ。横型の動画が投稿された場合も `object-fit: contain` で黒帯付きで収める。
- 攻撃方法のタブは 5 つになるため、ラベルは 2 行に折り返す（例：「ヒーロー／アクション」）。
- 「修正を提案」は **タイミング単位**。押すと、そのタイミング 1 つだけを入れた状態で投稿フォームを開く（`replaces_timing_id` を付けて送る）。
- 下部に固定ボタン「この組み合わせを投稿」を置く。キャラを選んだ状態で `/submit` を開く。
- 承認済みデータがない場合は「まだ情報がありません」と表示し、投稿ボタンを目立たせる。

### 4-4. 投稿フォーム

| 項目 | 必須 | 入力方法・制限 |
|---|---|---|
| ① 攻撃する側（自分）のキャラ | ○ | 画像付きセレクト（全キャラ） |
| ② HSを使う相手のキャラ | ○ | 画像付きセレクト（全キャラ） |
| 合わせるタイミング | ○ | **1 個以上、何個でも追加できる**（下記） |
| ニックネーム | 任意 | テキスト（最大 20 字）。前回の入力をブラウザに保存して次回の初期値にする。未入力なら表示しない |
| 応援コード | 任意 | テキスト（最大 20 字）。ニックネームの次に置く。前回の入力をブラウザに保存して次回の初期値にする。未入力なら表示しない |
| Turnstile | ○ | 送信ボタンの直前に表示 |

#### 合わせるタイミングの入力
1 キャラが 1 キャラに合わせるタイミングは 1 つとは限らないため、1 回の投稿で複数のタイミングを登録できるようにする。

- 各タイミングは、次の 5 項目をまとめた 1 ブロックとして入力する。**動画と備考はタイミングごとに 1 つずつ** 付ける。
  | 項目 | 必須 | 入力方法 |
  |---|---|---|
  | 攻撃方法 | ○ | ボタンで選ぶ：ヒーロースキル／通常攻撃／ヒーローアクション／スキルカード／その他（初期値：ヒーロースキル） |
  | 合わせる目印 | ○ | ボタンで選ぶ：ボイス／動き／時間／その他 |
  | 合わせるタイミング | ○ | 自由入力テキスト（最大 200 字） |
  | 備考 | 任意 | 複数行テキスト（最大 1000 字） |
  | 動画 | **○** | ファイル選択（1 タイミングにつき 1 本。6 章の制限） |
- ブロックの下に「＋ タイミングを追加」ボタンを置く。押すと新しいブロックを末尾に追加し、そこへスクロールする。新しいブロックの攻撃方法と目印は、直前のブロックと同じものを初期値にする。
- ブロックが 2 つ以上あるときは、各ブロックに「削除」ボタンを出す（最低 1 つは残す）。
- ブロックには「タイミング 1」「タイミング 2」…と番号を振る。並び順は表示順として保存する。
- 1 回の投稿で登録できるタイミングの上限は 20 個とする（無制限による負荷を避けるため）。
- 管理者の「編集して承認」でも、同じ入力ブロックを使う（追加・削除・編集ができる）。

#### 修正提案のときのフォーム
- 対象のタイミング 1 つだけを入力ブロックに入れて開く。
- **攻撃方法と合わせる目印は変更できない**（選択中のもの以外のボタンを無効化する）。
- 修正できるのは、合わせるタイミング・備考・動画。
- 「＋ タイミングを追加」と「削除」は表示しない。
- 上部に「公開中のタイミングの修正案として申請します。攻撃方法と合わせる目印は変更できません。」と表示する。

#### プレースホルダー
各ブロックで選んだ目印に応じて、そのブロックの「合わせるタイミング」のプレースホルダーを切り替える。

| 種類 | 合わせるタイミングのプレースホルダー |
|---|---|
| ボイス | `例：「いくよー！」の「よ」に合わせる　※セリフは「」で囲んでください` |
| 動き | `例：相手が武器を振り下ろし、地面に着いた瞬間` |
| 時間 | `例：相手のHS発動から約2秒後` |
| その他 | `合わせるタイミングを自由に入力` |

- カッコはアプリ側で自動では付けない（付与も除去もしない）。ボイスのときは、上記のプレースホルダーで利用者に「」を付けてもらうよう案内する。
- 将来カッコの自動付与に切り替えられるよう、表示は `formatCue(type, text)` という関数を 1 か所に作って通す。現時点では `text` をそのまま返す。

#### 送信の流れ
1. 送信前に **プレビュー** を表示する（詳細画面のカードと同じ見た目。動画も再生できる）。
2. 「この内容で申請」を押したら、6-2 の手順で動画をアップロードし、エントリを登録する。
3. アップロード中は進捗バー（%）を表示する。失敗したら再試行ボタンを出す。
4. 完了したら `/submit/done/:code` に移動し、**受付番号**（例：`HS-7K3Q9P`）を大きく表示する。
   - 「コピー」ボタンを置く。
   - 「この番号で審査状況を確認できます」と案内する。
   - 受付番号はブラウザ（localStorage）にも保存し、`/status` で自分の投稿一覧として表示する。

### 4-5. 審査状況の確認
- 受付番号を入力すると、その投稿の **タイミングごとの** ステータス（承認待ち／承認済み／却下）と内容を表示する。
- 却下されたタイミングは、却下理由（あれば）を表示し、動画は表示しない。
- このブラウザで投稿した受付番号の一覧も表示する（localStorage から読む）。
- 承認待ちのタイミングが残っている投稿は「承認待ちの分を取り下げ」できる。取り下げには、受付番号と一緒に発行する **取り下げ用キー** を使う（ブラウザに保存しておく）。

### 4-6. 管理：承認待ち一覧
- **審査はタイミング単位** で行う。1 回の投稿に複数のタイミングがあっても、1 つずつ承認・却下できる（正しいものだけ承認できるようにするため）。
- `status = 'pending'` のタイミングを、受付番号ごとにまとめて古い順に表示する。
  - まとまりの見出し：受付番号・投稿日・タイミング数（修正提案なら「修正提案」）。
  - 各タイミングに「タイミング 1 / 2」のような番号を付ける。
- 各タイミングは詳細画面と同じ見た目でプレビューし、動画も再生できる（承認前の動画は管理者だけが見られる。6-3 参照）。
- 修正提案は、**元のタイミングと並べて差分が分かるように** 表示する。
- 各タイミングのカードの下に、**承認／却下／編集して承認** の 3 つのボタンを横並びで置く。
  - **承認**：そのタイミングだけ `status = 'approved'` にし、動画を公開領域に移す（6-3）。修正提案の場合は、元のタイミングを修正案の内容で置き換え、修正案は `status = 'merged'` にする。置き換えで使われなくなった動画は削除する。これらは 1 つの処理（D1 の batch）で行う。
  - **却下**：理由を入力（任意）して、そのタイミングだけ `status = 'rejected'` にする。動画は削除する。
  - **編集して承認**：そのタイミング 1 つだけを編集してから承認する（タイミングの追加・削除はできない。修正提案の場合は攻撃方法と目印も変更できない）。
- 画面上部に **ストレージ使用量**（R2 の合計サイズ ／ 上限）を表示する。
- 一括操作は不要。

### 4-6-2. 管理：設定
設定値は D1 の `settings` テーブル（key / value）に保存する。

- **制作者の応援コード**：フッターに表示する値を入力・保存する。
- **注意事項**：複数行テキストで編集する。1 行が 1 項目。`**文字**` で太字。「初期の文面に戻す」ボタンあり。
- **このアプリについて**：複数行テキストで編集する。簡易的な書式に対応する（`## ` 見出し、`- ` 箇条書き、`1. ` 番号付きリスト、`**文字**` 太字、空行で段落の区切り）。HTML はそのまま表示せず、必ずエスケープしてから書式を当てる。「プレビュー」「初期の文面に戻す」ボタンあり。

### 4-7. 管理：キャラ管理
- キャラの追加・編集・並べ替え・削除ができる。
- 画像を設定したキャラには「画像を削除」ボタンを出し、画像を外せる（R2 からも削除する。削除後は頭文字の代替表示に戻る）。
- 並べ替えは各行の ▲▼ ボタンで 1 つずつ上下に移動する（`sort_order` を入れ替える）。この順番が、トップ画面・相手選択画面・投稿フォームのキャラの表示順になる。
- 項目：名前、slug（URL 用の英数字）、画像アップロード、表示順。
- 画像は R2 の `heroes/` 以下に保存する。アップロード時にブラウザ側で 256×256 の WebP に縮小する。

## 5. 表示ルール

### 5-1. キャラ画像
- 正方形にトリミングして表示する（`object-fit: cover`）。角丸あり。
- 画像が未登録のキャラは、名前の頭文字と背景色で代わりに表示する（背景色はキャラの ID から決める）。
- 画像には長期キャッシュ（`Cache-Control: public, max-age=31536000, immutable`）を付け、ファイル名にハッシュを入れる。

### 5-2. テキスト
- 投稿されたテキストは必ずエスケープして表示する（HTML として描画しない）。
- 改行は表示に反映する。

## 6. 動画の仕様

### 6-1. アップロードの制限
| 項目 | 制限 |
|---|---|
| 形式（選べるファイル） | MP4、MOV（iPhone の画面収録）、WebM |
| 長さ | **最大 30 秒**（ブラウザで `<video>` に読み込み、`duration` を確認する） |
| 元のファイルの大きさ | 利用者が気にしなくてよい（ブラウザで自動的に軽くするため）。ただし極端に大きいもの（500MB 超）はブラウザが固まるのを防ぐため断る |
| 保存される動画 | ブラウザで自動変換した MP4（H.264）。**1 本あたり最大 15MB**（サーバー側でも確認） |
| 本数 | **1 タイミングにつき 1 本（必須）**（1 投稿で複数本になる） |

- 30 秒を超える場合は、選択した時点で理由を表示し、送信できないようにする。
- サーバー側でも、署名付き URL の発行時に宣言されたサイズ（15MB 以下）と形式（`video/mp4`）を確認する。

### 6-1-2. ブラウザでの自動圧縮（必須）
iPhone・iPad の画面収録は 30 秒でも数十 MB になることが多いため、**アップロード前にブラウザ内で自動的に軽くする**。利用者は何も操作しなくてよい。

- 変換先：MP4（H.264 / AAC）、**縦型のまま短辺 720px**（例：720×1560 前後。元が小さければ拡大しない）、映像 2.5Mbps 前後、30fps、音声 96kbps。目安は 30 秒で約 10MB。
- 実装：WebCodecs を使う（例：`mediabunny` ライブラリ）。WebCodecs が使えないブラウザでは `ffmpeg.wasm` で変換する。
- 変換は「確認画面へ」を押したとき、または動画を選んだ直後に行い、**「動画を軽くしています… ○%」** と進捗を表示する。
- 変換後のファイルでプレビューを表示する（投稿される見た目をそのまま確認できるように）。
- 変換後も 15MB を超えた場合は、ビットレートを下げて 1 回だけ再変換する。それでも超えたら、動画を短くするよう案内する。
- 変換に失敗した場合は、理由を表示し、別の動画を選ぶよう案内する。
- 目安の保存本数：R2 の無料枠（約 9GB まで使用）で、1 本 10MB として約 900 本。

### 6-2. アップロードの流れ
動画は Worker を経由せず、**ブラウザから R2 に直接アップロード** する（Workers のリクエストサイズ上限を避けるため）。

1. ブラウザ → Worker：`POST /api/uploads`
   - 送るもの：Turnstile トークン、ファイルサイズ、Content-Type
   - Worker は Turnstile を検証し、8 章の容量チェックを通ったら、R2 の `pending/` 以下への **署名付き PUT URL**（有効期限 10 分）と `video_key` を返す。
2. ブラウザ → R2：署名付き URL に PUT する（進捗を表示する）。
3. ブラウザ → Worker：`POST /api/entries`
   - 送るもの：エントリ内容と、各タイミングの `video_key`（動画が複数ある場合は 1 と 2 を本数分くり返す）
   - Worker は `video_key` が実在するか、サイズが制限内かを R2 の `head` で確認してから D1 に登録する。
- 署名付き URL は R2 の S3 互換 API で発行する（`aws4fetch` などを使う）。R2 の CORS 設定も README に書く。

### 6-3. 保存場所と公開範囲
| プレフィックス | 中身 | 見られる人 |
|---|---|---|
| `pending/` | 承認待ちの動画 | 管理者のみ（Worker 経由。`/admin` 配下の API で配信） |
| `public/` | 承認済みの動画 | 全員 |
| `heroes/` | キャラ画像 | 全員 |

- 承認したら、`pending/` から `public/` にコピーし、`pending/` 側を削除する。
- 公開用の配信は `GET /media/*` の Worker ルートで行う。
  - `Range` リクエストに対応すること（動画のシーク再生に必要）。
  - 長期キャッシュを付ける。
- 独自ドメインを R2 に接続した場合は、`public/` と `heroes/` をそのドメインから直接配信できるよう、メディアのベース URL を環境変数 `MEDIA_BASE_URL` で切り替えられるようにする。

### 6-4. 自動削除（Cron Triggers、1 日 1 回）
- 却下・取り下げになったエントリの動画と、修正で置き換えられて使われなくなった動画を削除する。
- アップロードされたのにエントリが登録されなかった `pending/` の動画（24 時間以上経過したもの）を削除する。
- **14 日以上審査されずに残っている** 承認待ちの動画は、残すか削除するかを環境変数で選べるようにする（初期値：残す）。

## 7. データベース設計（D1）

### 7-1. テーブル

#### `heroes`
| カラム | 型 | 説明 |
|---|---|---|
| id | TEXT PK | ULID |
| name | TEXT UNIQUE NOT NULL | キャラ名 |
| slug | TEXT UNIQUE NOT NULL | URL 用（英数字・ハイフン） |
| image_key | TEXT | R2 のキー（`heroes/...`） |
| sort_order | INTEGER | 表示順 |
| created_at | TEXT | ISO 8601 |

#### `submissions`（1 回の投稿 = 1 行）
| カラム | 型 | 説明 |
|---|---|---|
| id | TEXT PK | ULID |
| code | TEXT UNIQUE NOT NULL | 受付番号（`HS-` ＋ 紛らわしい文字を除いた英数字 6 桁） |
| delete_key_hash | TEXT NOT NULL | 取り下げ用キーのハッシュ（SHA-256） |
| attacker_id | TEXT FK → heroes | 攻撃する側 |
| target_id | TEXT FK → heroes | HSを使う相手 |
| nickname | TEXT | 投稿者のニックネーム（最大 20 字。空なら表示しない） |
| support_code | TEXT | 応援コード（最大 20 字。空なら表示しない） |
| replaces_timing_id | TEXT FK → timings | 修正提案の対象タイミング（修正提案のときのみ） |
| created_at | TEXT | ISO 8601 |

#### `timings`（合わせタイミング 1 つ = 1 行。**審査もこの単位**）
| カラム | 型 | 説明 |
|---|---|---|
| id | TEXT PK | ULID |
| submission_id | TEXT FK → submissions | どの投稿で送られたか |
| attacker_id | TEXT FK → heroes | 攻撃する側（検索用に submissions から複製） |
| target_id | TEXT FK → heroes | HSを使う相手（同上） |
| position | INTEGER | 投稿内での順番（0 始まり） |
| attack_type | TEXT | `hs` / `normal` / `action` / `card` / `other`（ヒーロースキル／通常攻撃／ヒーローアクション／スキルカード／その他） |
| cue_type | TEXT | `voice` / `motion` / `time` / `other` |
| timing_text | TEXT NOT NULL | 合わせるタイミング（最大 200 字） |
| note | TEXT | 備考（最大 1000 字） |
| video_key | TEXT NOT NULL | R2 のキー（1 タイミングにつき 1 本、必須） |
| video_size | INTEGER | バイト数 |
| status | TEXT | `pending` / `approved` / `rejected` / `withdrawn` / `merged`。初期値 `pending` |
| reject_reason | TEXT | 却下理由 |
| reviewed_at | TEXT | 審査日時 |
| updated_at | TEXT | ISO 8601 |

- 1 回の投稿につき timings は 1〜20 行。修正提案は必ず 1 行。
- 投稿時は submissions と timings を 1 つの batch で書き込む。
- 修正提案を承認したときは、対象の timings 行の内容（timing_text・note・video_key など）を修正案の内容で更新し、修正案の timings 行は `status = 'merged'` にする。
- 文字数と列挙値は CHECK 制約でも縛る。API 側でも同じチェックをする（zod などで検証する）。
- インデックス：`timings(attacker_id, target_id, status, attack_type)`、`timings(status, submission_id)`、`submissions(code)`。
- 投稿者の IP アドレスなどの個人情報は保存しない。

### 7-2. 一般向けと管理者向けの API の分け方
- 一般向けの API（`/api/*`）は、`status = 'approved'` のタイミングしか返さない。
  - 例外：`/api/status/:code` は、その受付番号のタイミングだけを返す（ステータスに関係なく）。
- 管理者向けの API（`/api/admin/*`）と画面（`/admin/*`）は、Cloudflare Access で保護する。
  - **管理画面への入り方**：一般向けの画面にはリンクを置かない。管理者は `https://（アプリのURL）/admin` を直接開く（ブックマークやホーム画面への追加を推奨）。開くと Cloudflare Access のログイン画面が出て、登録済みのメールアドレスに届くワンタイムコードでログインする。
  - Worker 側でも、Access が付ける JWT（`Cf-Access-Jwt-Assertion` ヘッダー）を検証し、二重に確認する。
  - Access のチーム名と AUD は環境変数で設定する。

## 8. 荒らし対策と課金を防ぐ安全装置

ログインがないため、次の対策を組み合わせる。**投稿数の制限は設けない。**

### 8-1. 荒らし対策
- **承認制**：承認されたものだけを公開する。未承認の動画は一般の利用者からは見えない。
- **Turnstile**：投稿と動画アップロードの前に必ず検証する（ボットによる大量投稿を防ぐ）。
- **文字数と動画サイズの上限**：フロントとサーバーの両方で確認する。

### 8-2. 課金を防ぐ安全装置（必須）
R2 は支払い方法を登録して使うため、無料枠を超えると課金される。これを防ぐため、次を実装する。

- R2 の **合計使用量を D1 で記録** する（アップロード・削除のたびに増減する。Cron でも実際の値と照合する）。
- 合計が **9GB を超えたら、新しい動画のアップロードを受け付けない**。文字だけの投稿は引き続き受け付ける。
  - 投稿フォームに「現在、動画の受付を停止しています」と表示する。
  - 上限値は環境変数 `STORAGE_LIMIT_BYTES` で変えられるようにする。
- **承認待ちの動画の合計が 2GB を超えたら**、承認待ちが減るまで動画のアップロードを止める（審査が追いつかないうちに容量を使い切るのを防ぐ）。
- 管理画面に使用量を表示する（4-6）。

## 10. デザイン

**見た目は試作版（`hs-awase.html`）を正とする。** 色・余白・角の形・文字サイズは、試作版の CSS をそのまま移植し、勝手に変えない。

### 10-1. テーマ
**白背景** に、オレンジと黒をアクセントとして使う、すっきりしたサイバー調。余白を広めに取り、窮屈に見えないようにする。

| トークン | 値 | 用途 |
|---|---|---|
| `--bg` / `--panel` | `#ffffff` | 背景・カード（補助パネルは `#fafafa`） |
| `--line` | `#dedede` | 枠線（実線で、途切れさせない） |
| `--text` | `#000000` | 本文・見出し |
| `--sub` | `#666666` | 補足テキスト |
| `--accent` | `#ff6a00` | オレンジ（塗り・線・選択中の攻撃方法・主要ボタン） |
| `--accent-t` | `#c94f00` | 白地に置くオレンジの文字（読みやすさのため濃いめ） |
| `--ok` / `--danger` | `#1a9e5c` / `#d93636` | 承認済み／却下（管理画面・審査状況のみ） |
| `--void` / `--void-t` | `#2fd3ef` / `#0a93ad` | Voidoll の水色をイメージした差し色（公式の色指定ではない）。目印チップ、キャラボタンの斜線模様、タイミング文字の左線、VS の攻撃する側の枠、背景の一部など |

### 10-2. 文字
- 英数字：Chakra Petch（Google Fonts、500 / 700）
- 日本語：Zen Kaku Gothic New（Google Fonts、400 / 500 / 700）
- `font-feature-settings: "palt"` で日本語の字間を詰める。

### 10-3. 形
- 角丸は使わない（四角）。枠線は 1px の実線。
- **角を斜めに切り落とす形は、ポイントだけに使う**：主要ボタン（投稿・申請）、下部の固定ボタン、選択中の攻撃方法タブ。それ以外の枠には使わない（線が途切れて見えるため）。
- ヘッダー下に 2px の黒い線を引き、その上に **進み具合を示すオレンジの線（4px）** を重ねる。画面が進むごとにオレンジの線が右へ伸びる（0.7 秒のアニメーション）。
  - トップ（① 攻撃する側）：1/3 → HSを使う相手の選択（②）：2/3 → タイミング詳細：右端まで
  - 投稿フォーム：入力 1/3 → 確認 2/3 → 投稿完了：右端まで
  - その他の画面（このアプリについて・審査状況・管理画面）：左端に短く表示
  - 戻ったときは、前の長さから縮むように動かす。
- セクション見出しは、左にオレンジの小さな四角、右に細い線。
- タイミングのカードは、左端に 4px のオレンジの線。タイミングの文字は薄いグレー地に黒字で、左に黒い線。
- 詳細画面の VS 表示では、「HSを使う相手」の画像だけをオレンジの枠で囲む。
- キャラ一覧のカードには **件数の数字を表示しない**（攻撃する側の一覧・HSを使う相手の一覧とも）。HSを使う相手の一覧は「登録済み／未登録」の見出しで分ける。

### 10-3-2. 背景
- 白の上に、薄い方眼（24px）と、回路のような細い線のパターン（240px ごとのタイル、SVG）を重ねる。
- 画面右上に、コンパスの照準リング（同心円・目盛り・方位の針。オレンジ、SVG）を大きく薄く配置し、90 秒で 1 回転させる。
- 背景は固定し、スクロールしても動かさない。カードは白地で、背景の上でも文字が読めるようにする。

### 10-3-3. ボタンの見た目
- **押せるものは、ボタンだと分かる見た目にする**：枠線と、**右下に 3px ずらした影**（`rgba(0,0,0,.55)`、主要ボタンは `.62`）を付ける。枠線は黒（`#000`）。押すと影の分だけ右下に沈む。
- 主要ボタン（投稿・申請・下部の固定ボタン）はオレンジ地に黒文字、斜めカットの形。
- キャラのカードも同じく右下の薄い影付き。枠は薄いグレー。**水色のドット模様を、右下が濃く左上に向かって消えていくグラデーション** で入れる（角の三角やかぎ括弧のような飾りは付けない）。マウスを乗せると影がオレンジになる。
- 画像がないキャラの代替表示は、**グレーの地に名前の先頭の文字** だけ（方眼などの模様は入れない）。
- 動画の有無を示すマーク（🎬 など）は付けない。
- 選択中のタブ（攻撃方法タブ・管理画面のタブ）と攻撃方法ボタンは、オレンジ地に黒文字。合わせる目印の選択中は黒地に白文字。
- チップ（攻撃方法・目印・ステータス）は押せないので、段差を付けない。

### 10-3-4. 動き（アニメーション）
- **画面に入ったとき**：ヘッダー下の線が左から伸び、タイトルが一瞬ずれて表示される（グリッチ）。カード類は左から走査するように順番に表示する（1 つあたり 28ms ずつ遅らせる、最大 560ms）。表示の最後に明るさや色が変わらないようにする。同じ画面内の再描画（検索入力など）では再生しない。
- **背景**：動きは控えめにする（目が回らないように）。照準リングがごくゆっくり回転する（4 分で 1 回転）だけで、点滅や走査線は入れない。
- **詳細画面**：「HSを使う相手」の照準枠が外から絞り込まれてロックオンし、その後、波紋が一定間隔で広がる。「HS明けに合わせる」の文字がゆっくり明暗する（点滅はさせない）。
- **下部の固定ボタン**：光が左から右へ走る。
- **選択の切り替え**：選んだ攻撃方法・目印のボタンが軽く弾む。
- `prefers-reduced-motion: reduce` の利用者には、すべての動きを止める。

### 10-4. その他
- タップしやすさを優先し、ボタンの高さは 44px 以上にする（カード内の小さいボタンを除く）。
- 動画は横幅いっぱいで表示し、`playsinline` と `preload="metadata"` を付ける。
- キーボード操作時のフォーカスは、オレンジの枠で見えるようにする。ただし検索欄などのテキスト入力欄は、タップしてもオレンジの枠を出さない。

## 13. 完成の条件

- [ ] ログインなしで、トップ → 相手選択 → 詳細まで見られる
- [ ] ログインなしで投稿できる。投稿後に受付番号が表示される
- [ ] 承認待ち・却下のエントリと動画は、一般の利用者からは（API や URL を直接叩いても）見えない
- [ ] `/admin` は Cloudflare Access を通らないと開けず、Worker 側でも JWT を検証している
- [ ] 管理者が承認すると、詳細画面にすぐ表示され、動画も再生できる
- [ ] 承認待ち一覧で、1 回の投稿に含まれる複数のタイミングを 1 つずつ承認・却下・編集して承認できる
- [ ] 修正提案は 1 つのタイミングに対して 1 つだけ送れる（タイミングの追加ができない）
- [ ] 修正提案を承認すると、対象のタイミングだけが置き換わる
